# 公网免密访谈入口

用户要求访谈网页不再输入密码。直接撤销全站密码会公开既有病例，因此改为独立访客网关：免密开放访谈，保留医生身份验证与已有病例保护。

## 访问方式

- 公网 `/`、`/guardian`、`/child` 免密。
- `/clinician`、`/doctor`、医生接口、旧管理接口、病例列表、演示重置等继续使用原医生账号密码。
- 匿名访客创建的新会话绑定当前浏览器的随机256位访客Cookie。Cookie为Secure、HttpOnly、SameSite=Lax，服务端只保存其哈希。
- 查看、继续、停止访谈，上传及播放录音、查看报告，仅限该访客自己创建的会话。知道旧sessionId或mediaId也不能读取其数据。
- 病例关联使用医生签发的7天有效、限定病例与回答者角色的签名入口。裸caseId不能使公网访客加入已有病例。局域网原入口继续兼容原来的明确关联流程。
- 网关只提供构建产物，不向公网暴露Vite开发文件服务、`/@fs`、源码、配置、数据库或任意文件路径。

## 运行

保持原后端4176和本地前端5176不变。网关单独监听`127.0.0.1:5178`，固定HTTPS隧道转发到5178。医生密码在网关校验，公网隧道自身无需再向访谈用户索取密码。

```sh
npm run build
npm run dev:public
```

入口文件：`server/public-gateway.mjs`。访客归属表：`server/data/run/public-session-access.db`，权限600，不保存原始患者回答或明文Cookie。

医生复制病例入口时，前端向`/api/previsit/access/invitations`申请签名；只有已验证的医生能调用此接口。前端将签名随创建会话请求提交，签名不作为已有病例的读取权限。

## 验证

`npm run public:regression`使用真实后端、临时SQLite与合成病例，38项检查通过，覆盖：免密页面、旧病例/列表/管理接口保护、访客间隔离、伪造及重复Cookie、继续和停止访谈、录音归属、签名入口及篡改/错角色/错病例拒绝、跨站写入阻断、配置及数据库路径阻断、网关重启后归属保持。

此次没有取消医生身份验证，也没有把已有病例或录音改为公开数据。使用新浏览器或清理Cookie后，访客不能再读取旧浏览器的会话；医生仍可通过原工作台访问。
