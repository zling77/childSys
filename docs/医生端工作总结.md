# ChildPsych 医生端工作总结

> 整理日期：2026-10-07。依据项目当前源码、README、设计说明及测试文件整理。本文描述当前可核实的实现，不代表临床有效性验证或正式上线验收。

## 1. 工作定位与总体成果

项目已实现独立的医生端预问诊工作台，入口为 `/clinician`。工作台将家长或儿童预问诊过程中采集的回答整理为患者概览、结构化摘要、风险相关原话、重要异常、缺失信息及可追溯的证据明细，供医生在正式面诊前查阅。

目前形成的主要链路为：

**预问诊回答 → 证据抽取与状态更新 → 结构化医生包 → 医生工作台查阅 → 原文及音视频核实。**

系统定位是面诊前的信息整理工具。当前医生端不生成诊断结论、风险等级、治疗建议或正式面诊问题，由医生自行决定面诊内容。

## 2. 已实现的医生端功能

### 2.1 独立入口与工作台布局

- 建立独立医生端路由，和家长端、儿童端使用统一的全局侧栏及视觉风格。
- 采用暖白色、青绿色和圆角卡片，按临床查阅顺序组织信息。
- 主区域依次展示患者概览、结构化预问诊摘要、需优先核实、来源差异与时序变化、采集过程明细，以及存在记录时的音视频附件。
- Agent 执行过程、策略日志和模型审计不接入当前医生工作台展示链路。

### 2.2 预问诊会话队列

- 展示年龄、年级、主诉、会话状态、采集完整度和问答轮次。
- 支持按全部、进行中、已完成、需优先核实、草稿筛选。
- 支持手动刷新，并每 3 秒自动刷新队列。
- 刷新时保留当前选中的会话；只有当前会话不在返回队列中时，才选择首条会话。
- 对存在风险线索的会话显示“需优先核实”提示。
- 后端按更新时间倒序返回队列，当前上限为 50 条。

这里的队列实际按 `sessionId` 管理，是预问诊会话列表，尚不能等同于完整的患者档案或医院预约队列。

### 2.3 患者概览

选中会话后，展示会话编号、年龄、性别、年级、主诉原文、采集完整度和当前状态，帮助医生快速了解本次预问诊背景。

“采集完整度”来自系统的信息覆盖计算，不是诊断可信度或临床评估充分性的评分。

### 2.4 结构化预问诊摘要

后端已实现 `PrevisitPacket` 医生包生成，当前首屏摘要重点展示：

| 展示模块 | 内容 |
|---|---|
| 预问诊摘要 | 主诉、主要表现、病程、功能影响、相关背景及风险原话数量的文字汇总 |
| 主要表现 | 本次主要困扰和具体表现 |
| 病程与频率 | 起始时间、变化过程、频率、持续时间及程度等已采集信息 |
| 功能影响 | 学习、生活、自理和人际关系等方面的影响 |
| 诱因与背景 | 诱因、近期事件、不同场景及家庭背景 |

医生包还保存躯体与发育史、既往求助与干预、求助诉求和优势支持资源等字段，但当前首屏摘要没有将这些内容全部作为独立分区展示。相关信息可结合采集覆盖状态及证据原文查看。

报告按细分字段读取信息，保留分轮采集的频率、程度等内容，避免只展示某个主题最后一次回答。

**当前摘要由规则和模板拼接生成。** 项目中的 LLM 主要用于受约束的动态追问、澄清或影子抽取审计，不能将医生摘要描述为已实现 LLM 自由生成的临床总结。

### 2.5 风险、重要异常与缺失信息

“需优先核实”区域分为三个部分：

| 部分 | 已实现的处理 |
|---|---|
| 风险相关原话 | 保留触发表述、来源、问答轮次，提示医生当面核实 |
| 重要异常与变化 | 汇总规则识别的功能影响、睡眠或躯体变化、发育与健康史异常，以及冲突或不确定信息 |
| 缺失与待核实信息 | 列出未获得可用信息、来源冲突或仍不明确的主题及字段 |

风险提示不输出高、中、低风险分层。“未记录风险相关原话”仅说明系统没有记录到相应表述，不能解释为已排除风险。

异常识别包含否定语义处理，避免把“没有睡眠问题”等正常或否定描述直接列为异常；但其规则识别能力仍需更多真实语境评估。

### 2.6 来源差异与时序变化展示

- 保留同一主题下不同来源或不同轮次的原始表述。
- 显示来源、状态、不同描述和关联证据编号。
- 根据已有状态与观察记录，展示一致信息、后续补充、来源冲突或待核实关系。
- 后续回答用于补充状态时，保留既有证据，便于医生查看前后描述。

当前关系由状态及文本差异规则归纳。它展示的是问答轮次中的证据变化，不能直接等同于经过验证的疾病病程推断或长期随访模型。“信息修正”虽存在显示标签，但当前关系构建函数未生成独立的修正关系。

### 2.7 问答时间线、证据原文与覆盖状态

“采集过程明细”提供三个默认折叠的查阅入口：

1. **问答输入时间线**：按轮次展示系统提问和对应回答，使用稳定的 QA ID 关联问答，并显示回答来源、采集主题及证据编号。
2. **证据原文追溯**：以表格展示证据 ID、来源、轮次、主题、时间范围、当前主题状态和原文。
3. **采集覆盖状态**：展示各主题的当前内容及状态，包括已采集、部分信息、缺失、待核实和来源冲突。

只有同一会话存在两个及以上输入来源时，时间线才标为“多源问答时间线”，并分别统计监护人、患儿等来源。状态文案使用“已采集”，避免将采集结果表述为“已确认”。

### 2.8 音视频附件核实

- 仅在会话有媒体记录时展示附件区域。
- 支持音频和视频播放，以及原始文件下载。
- 展示媒体类型、时长、文件大小、记录轮次及关联问题或采集目标等元数据。
- 媒体文件存于本地目录，SQLite 保存元数据，医生端通过媒体接口读取文件。

目前支持的是媒体回放核实。未见医生端自动分析表情、行为或声音特征的实现。连续录制文件也不能据此视为已实现每条证据与媒体片段的精确时间定位。

### 2.9 摘要生成、更新与版本管理

- 正常结束预问诊或主动停止时生成医生包。
- 尚无医生包时，医生端提供“生成预问诊摘要”入口。
- 界面根据会话和医生包时间判断是否存在新证据，并提供更新入口。
- 后端比较新旧医生包内容：内容相同则返回既有版本，内容变化才保存新版本。
- 展示医生包版本和更新结果提示。
- 单独生成医生包不修改预问诊会话状态。

医生包保存为 `machine_draft`。当前未见医生编辑、签署或确认报告的完整流程，也未见报告历史版本比较界面。

### 2.10 演示病例工具

医生端提供默认折叠的演示数据工具，可生成或清空演示病例。生成演示病例的后端接口会先清空现有演示数据，再创建病例，不能描述为单纯追加病例。

## 3. 后端与数据支持

| 接口 | 用途 |
|---|---|
| `GET /api/previsit/doctor/queue` | 获取会话队列，支持状态筛选 |
| `GET /api/previsit/packet/:sessionId` | 获取最新医生包 |
| `POST /api/previsit/packet/:sessionId/generate` | 生成或更新医生包，无变化时复用既有版本 |
| `GET /api/previsit/evidence/:sessionId` | 获取问答、证据、风险线索与主题状态 |
| `GET /api/previsit/media/:sessionId` | 获取媒体记录列表 |
| `GET /api/previsit/media/blob/:mediaId` | 获取媒体文件，供播放或下载 |
| `POST /api/previsit/demo/seed` | 重建演示病例 |
| `POST /api/previsit/demo/reset` | 清空演示数据及关联媒体 |

SQLite 持久化会话、问答、证据单元、主题状态、风险线索、医生包版本和媒体元数据。医生包包含信息契约版本，便于识别报告生成时采用的字段结构。

## 4. 当前边界与尚未完成的工作

以下是当前实现范围之外或仍需验证的能力，不应作为已完成成果表述：

- **跨会话患者关联**：已支持同一会话内多来源证据展示，但未见同一患儿家长端与儿童端独立会话的自动关联、合并流程。
- **更多来源接入**：界面存在教师、量表、既往记录等来源标签，但标签本身不能证明已有对应导入接口或完整采集流程。
- **医生反馈闭环**：未见报告编辑、证据纠正、风险复核关闭、签署确认及反馈驱动状态更新的完整工作流。数据库中的 `doctor_edit_json` 字段不等于该功能已完成。
- **队列与详情同步**：每 3 秒刷新的是队列；当前所选会话详情主要在切换会话或手动生成摘要后加载，不能声称摘要和证据明细均实时刷新。
- **完整报告交付**：当前未见医生报告的 Markdown、PDF 导出或医院病历系统对接功能；原始媒体下载已实现。
- **身份与权限**：当前服务代码未见医生登录、角色鉴权和患者数据访问控制，仍属于 P0 演示原型。
- **服务状态检测**：侧栏“预问诊服务在线”为固定显示文案，不能作为实时健康检查结果。
- **临床效果验证**：未见可证明节省医生时间、提高评估准确性或改善临床结局的研究结果，需要单独设计验证。

## 5. 验证情况

本次实际运行 `node scripts/core-regression.mjs`，**59 项核心回归检查通过**。其中包括医生包结构化输出、分轮字段值保留、可选字段冲突纳入报告、儿童自述标记，以及正常与异常睡眠/发育信息区分等检查。

项目已编写医生端浏览器测试，覆盖首屏顺序、内部日志隐藏、默认折叠、无媒体时隐藏附件、刷新保持会话选择、多来源问答追溯及无变化时版本保持等场景。**本次未运行浏览器测试，因此不声称这些界面用例已在本次验收通过。**
