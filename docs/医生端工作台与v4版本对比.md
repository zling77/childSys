# 医生端工作台与 v4 版本对比

> 对比日期：2026-10-07。以两个文件夹的实际源码为依据，未运行两个版本的浏览器界面对照或真实病例评估。

>
> 当前版本：`/Users/linn/Downloads/ChildPsych/`

## 1. 核心结论

**当前版本的医生端工作台主体与给定 v4 版本完全一致，没有发现新的工作台页面模块、布局重构或医生操作流程。**

前一份《医生端工作总结》描述的是当前已经具备的功能，其中病例队列、结构化摘要、风险与缺失信息提示、多来源证据展示、问答追溯、音视频播放和报告版本管理，在给定 v4 中已经存在，不能据此列为“相对 v4 新增的工作”。

可核实的变化主要有三类：

1. **医生端直接受到影响的访问配置变化**：默认接口地址改为同源 `/api`，新增开发代理配置。
2. **报告元数据变化**：初诊信息契约版本从 `1.0.0` 改为 `2.0.0`，医生包随之记录新契约版本。
3. **上游采集流程变化**：语音输入和动态追问机制调整，可能改变进入医生端的回答、问答顺序及采集结果，但医生端展示和报告生成代码没有相应重写。

## 3. 确实存在的直接及元数据变化

### 3.1 默认接口地址改为同源访问

| 项目 | 给定 v4 | 当前版本 |
|---|---|---|
| `API_BASE` 默认值 | `http://127.0.0.1:4176/api` | `/api` |
| 显式配置 | 支持 `VITE_API_URL` 覆盖 | 仍支持 `VITE_API_URL` 覆盖 |
| Vite 配置 | 给定文件夹没有 `web/vite.config.mjs` | 新增该文件，代理 `/api` 和 `/health` 到本地后端 |

**对医生端的影响：** 队列、摘要、证据、媒体列表和媒体文件请求，默认改为通过当前网页所在服务访问。远程访问前端时，可避免默认请求访问者自己电脑上的 `127.0.0.1:4176`。

开发配置还指定监听地址及允许访问的域名。生产部署仍需配置相应接口转发；Vite 开发代理本身不等于生产部署已经完成。

依据：当前 `web/src/main.jsx:9`、`web/vite.config.mjs`。

### 3.2 医生包中的信息契约版本变化

`core/intakeContracts.mjs` 的 `INTAKE_CONTRACT_VERSION` 从 `1.0.0` 改为 `2.0.0`。两版相同的 `core/packet.mjs` 会将这个常量写入医生包的 `intake_contract_version` 字段，因此新生成的医生包会记录 `2.0.0`。

这里变化的是**信息契约版本**，不是界面显示的“医生包版本 N”。后者仍按既有保存逻辑递增。当前医生工作台也未新增契约版本的展示模块。

该契约调整主要移除了字段定义中的固定追问文案，转向信息目标驱动的追问方式；不能据此声称新增了报告章节。

## 4. 上游变化及其对医生端的间接影响

### 4.1 动态追问从固定目标改写转向候选目标选择

给定 v4 的相关逻辑主要限制 LLM 改写规则已经选定的字段问题。当前版本新增 `dynamicGoalSpace.mjs` 和 `followupStrategy.mjs`，向模型提供受约束的候选信息目标，并校验目标选择及问题表达。

医生端仍使用相同时间线和摘要组件，但实际采集的主题顺序、问题文字及后续回答可能变化。

**可报告的改动：** 调整预问诊追问策略，为医生端提供信息的采集路径发生变化。

**尚不能报告的结论：** 医生摘要更准确、缺失信息更少或查阅效率更高。上述效果需要对照数据验证。

### 4.2 安全线索处理和动态问题兜底调整

- 当前版本在已有未关闭安全线索时，限制普通动态问题生成；普通澄清分支也增加了安全线索约束。
- 对模型生成的问题增加显著线索连续性校验；不满足条件时拒绝采用，并尝试信息目标驱动的兜底问题。
- 模型失败或问题被拒绝时，记录兜底结果和拒绝原因。

这些变化影响问诊下一步的选择和内部日志。医生工作台上的风险原话、风险提示和缺失信息模块保持原样；`core/risk.mjs` 风险识别代码也完全一致。

因此不能将这些变化写成“新增医生端风险分层”或“新增医生审计页面”。

### 4.3 语音转写及播报流程调整

当前版本调整了语音输入状态提示、最终识别结果写入、停顿后继续识别及识别文本拼接，并修改语音播报流程与参数；服务端增加神经语音合成接口。

这些是家长端、儿童端及共用语音链路的变化。它们可能影响最终提交给医生端的回答文本，但没有新增医生端语音转写编辑器、媒体自动分析或证据定位功能。

### 4.4 不属于医生工作台的页面调整

共用 `HeaderBlock` 移除了进度条，受影响的是使用它的问诊页面。医生端患者概览仍使用自己的采集完整度组件，其代码一致，不能将此项描述为“移除医生端完整度展示”。

## 6. 两个版本共同存在的限制

下列能力在当前版本未见补齐，不能列为相对 v4 的完成项：

- 同一患儿的家长、儿童独立会话自动关联与合并。
- 医生编辑报告、纠正证据、签署确认及风险复核关闭的完整反馈流程。
- 教师、量表、既往病历等来源的完整接入流程。
- 医生报告导出及医院病历系统对接。
- 医生登录、角色权限与患者数据访问控制。
- 音视频自动分析以及证据与媒体片段的精确时间定位。
- 当前选中会话详情的持续自动刷新；已有 3 秒刷新针对队列。

## 7. 可直接用于汇报的表述

> 与提供的 v4 源码相比，当前版本保留了原有医生工作台的布局、结构化摘要、风险及缺失信息展示、证据追溯、音视频回放和报告版本管理，未新增医生端业务模块。相关改动主要是将默认接口访问改为同源代理方式，并使医生包记录新的信息契约版本。同时，上游预问诊的语音转写、动态目标选择、安全线索优先处理及问题兜底机制有所调整，可能改变医生端接收的问答和证据内容。上述采集改动是否提高报告质量，仍需通过对照测试或临床评估确认。

## 8. 本次验证范围

本次结论来自静态源码差异和代码段一致性核实，没有运行双版本浏览器或数据库对照测试。此前当前项目的 59 项核心回归检查通过，但这不等于证明其相对 v4 的临床效果提升。此前数据库验收因当前 macOS 无法加载现有 `better-sqlite3` 原生二进制而未能执行。
