# 跨来源关注与独立取证

## 本次实现范围

在明确关联的同一病例中，每轮预问诊实时整理本人证据、刷新病例级证据关系，并将其他直接来源涉及的领域转换为中性追问目标。其他来源的原话、症状肯否、频率、程度、证据编号和关系判断不传入当前受访者的 Policy/Critic 或 Realizer 输入，不合并进其本人证据状态。

儿童与家长可在不同时间分别完成访谈；系统不要求同时在线，不根据年龄、姓名或主诉自动匹配病例。

## 如何使用

1. 在医生工作台选择正确病例，展开“本病例的独立预问诊入口”，分别复制儿童端或家长端入口。
2. 入口形式为 `/child?caseId=...` 和 `/guardian?caseId=...`。只为同一患儿使用相应入口。
3. 已有独立会话也可在医生端“材料与历史”中明确关联到该病例。
4. 普通 `/child`、`/guardian` 入口继续创建各自独立病例，不读取其他病例的关注提示。
5. 移出关联后，后续轮次不再使用被移出的来源；已生成的历史报告仍保持原版本。

## 每轮的实现流程

```text
当前回答 → 本会话证据与状态更新
         → 当前病例图加入本轮待保存证据，识别关系
         → 私有关注投影（仅领域/证据项 ID）
         → 与本人信息缺口共同形成候选
         → Policy + Critic 选择 → Realizer 生成
         → 语义及独立取证边界检查 → 显示问题
         → 保存本人回答、证据、决策及私有审计
```

跨来源关注是候选优先提示，并不强制模型永远选择对应问题。风险流程、用户停止、24轮硬上限和必要的当前回答澄清优先。每轮都会刷新关注；当上一问需要澄清时，可以先修复当前对话，再进入常规候选选择。

### 来源选择与抑制

- 图、证据及当前会话必须属于同一 `caseId`。
- 排除同一会话、同一回答者角色、转述来源、已更正或已删除证据。
- 安全线索不进入普通跨来源关注投影，继续由独立安全流程处理。
- 目标去重，每轮最多3项关注。已由本人解决的证据项不重开。
- 明确拒答、不知道、不记得、没有观察机会，按本人历史记录抑制该跨来源目标，不推断为“正常”或“不存在”。
- 同一目标最多2次实际询问；短答、沉默或“不知道为什么”本身不被推断为拒答。

### 睡眠示例

儿童原话：“最近天天睡不好。”

家长端内部只获得 `sleep_appetite_physical / sleep_change` 及中性独立取证标记。

可显示：“最近孩子晚上的睡眠，您能观察到哪些情况？”

不可显示：“孩子说最近天天睡不好，您是否也发现了？”

家长报告睡眠正常时保留家长自己的证据；未观察到或不知道时保留来源范围与未知，不能据此否定儿童主观体验。原有关系识别继续考虑来源、场景、时间、观察范围和明确更正，避免把非观察直接判为相反证据。

## 动态策略接入

保持现有一个底座、两次生成调用：第一次 Policy/Critic，第二次 Realizer。新增来源关注投影是服务器端确定性处理，不额外调用模型。

`sleep_change` 是条件性目标，未增补到18项必需证据契约，不改变14域覆盖计算。其他领域投影到现有必需目标。关注提示参与候选排序：睡眠提示加1.4，其他提示加0.5；这是首版启发式权重，不是学习出的VoI或临床收益估计。

Prompt新增 `elicitation_mode: independent`：关注目标不代表已证实异常；只问当前回答者自己能够观察或体验的情况。首次独立睡眠取证使用完整中性开放句式检查，防止未经证实的异常、频率、程度或另一来源说法。生成失败或越界使用中性目标回退问句。

## 留痕与患者接口

完整审计写入现有 `model_audit_log`，任务名为 `source_independent_focus`，记录触发证据ID、关系ID、排除原因、选中目标及 `collectionMode`。不需要数据库迁移。

医生病例接口返回 `interviewFocusAudits`。患者会话接口及旧决策日志接口使用白名单投影，移除私有关注审计、模型原始输出、推理理由和候选细节，保留本人状态与最终问题。未使用跨来源关注的旧会话保持原日志格式。

研究记录标明 `cross_source_triggered` 和 `independentCorroboration: false`：题目即使不透露另一端答案，领域选择仍受另一来源影响，不能称为完全独立验证。

## 验证结果与边界

新增 `npm run source:regression`：30项纯函数检查、20项真实HTTP链路检查通过。HTTP测试启动真实服务器、临时SQLite、真实上下文编译和持久化流程，仅模型响应使用受控fixture，所有病例均为合成数据。覆盖同病例触发、不同病例隔离、双模型输入、患者日志、拒答/未知、实时更新、移出关联、越界输出与模型失败回退。此结果验证实现行为，不代表真实模型的临床有效性或患者接受度。

原有59项核心回归、契约/上下文/预算/Provider/持久化检查、32项医生端回归、20项工作台回归、22项医生LLM回归及前端构建通过。

新增2项实际浏览器检查通过：复制两端病例入口；通过家长入口完成基本资料、同意、设备检测和主诉后，验证病例关联及本人证据隔离。浏览器使用受控设备/语音模拟，未将真实摄像头或真实音色效果计入本次验证。

服务已重新启动，前后数据库表计数一致、`quick_check`为`ok`，原有12个病例、77轮对话保留；后端新审计字段与前端病例入口均已载入。本次未调整页面CSS或语音配置。

本次完成的是正常访谈流程的来源盲化与数据投影隔离。现有医生病例API尚无身份鉴权，不能将页面/API投影称为完整的访问权限隔离；医生身份鉴权与接口授权需另行完善。

多来源效度背景参考：[De Los Reyes et al., 2015, The Validity of the Multi-Informant Approach to Assessing Child and Adolescent Mental Health](https://pmc.ncbi.nlm.nih.gov/articles/PMC4486608/)。本文支持重视信息来源与情境差异；本系统的目标投影、Prompt和审计设计为本项目的工程实现，不是论文直接提出的算法。

## 主要文件

- `core/sourceIndependentFocus.mjs`：病例图到中性目标的私有投影。
- `core/orchestrator.mjs`、`core/planner.mjs`：逐轮状态更新与关注候选接入。
- `core/llm/dynamicGoalSpace.mjs`：条件性睡眠目标与中性回退。
- `core/llm/contextCompiler.mjs`、`core/llm/promptRegistry.mjs`：两次模型调用的中性任务配置。
- `core/llm/independentElicitationBoundary.mjs`：来源及异常预设检查。
- `core/publicDecisionLogs.mjs`、`server/index.mjs`：私有审计、病例刷新及患者日志投影。
- `web/src/main.jsx`、`web/src/ClinicianWorkbench.jsx`：明确病例入口与关联传递。
- `scripts/source-independent-focus-unit.mjs`、`scripts/source-independent-focus-smoke.mjs`：新增回归。
